# Tiara2 v2.3.0 bootstrap: freeze v2.2.0, reclaim storage, then redesign

## What this package does

It does **not** delete anything during installation. It adds two commands:

- `tiara2 freeze-baseline`: verify and freeze the exact v2.2.0 model inputs,
  published model pack, resolved configuration, reports and checksums.
- `tiara2 cleanup-baseline`: create a deletion plan, then optionally apply that
  exact plan after explicit confirmation.

The authoritative reproduction input is the exact bp-balanced `train` and
`validation` FASTA under `train.train_ready`. Dense feature caches, sequence
packs and source copies are derived and can be removed after the freeze passes.

## Required config block

```yaml
baseline_freeze:
  freeze_dir: "{base}/baselines/v2.2.0"
  training_splits: [train, validation]
  benchmark_paths: []       # add benchmark FASTA/truth files before cleanup
  extra_keep_paths: []      # any irreplaceable local data
  extra_metadata_files: []  # small manifests/tables to copy into the freeze
  extra_delete_paths: []    # optional Tiara2-only roots; never data_home itself
```

## Exact runbook

### 1. Install the patched package

```bash
cd tiara-v2.3.0-bootstrap
pip install -e .
```

### 2. Add benchmark paths to config

Do this before freezing. Every benchmark FASTA, truth TSV, split manifest or
irreplaceable local file that must survive belongs in `benchmark_paths` or
`extra_keep_paths`.

### 3. Freeze v2.2.0

```bash
tiara2 freeze-baseline --config config/config.yaml --tag v2.2.0
```

This hashes the exact train/validation FASTA and the published model pack. Use
`--metadata-only` only if the full training-data hash is temporarily too slow;
do not release upstream data after a metadata-only freeze.

### 4. Inspect the safe cleanup plan

```bash
tiara2 cleanup-baseline --config config/config.yaml \
  --freeze-dir /data/shouhanyu/Tiara2/baselines/v2.2.0 \
  --profile safe
```

Safe profile targets feature cache, seqpack, flat data, old checkpoints and the
work tree. It never removes source/corpus data.

### 5. Apply safe cleanup

```bash
tiara2 cleanup-baseline --config config/config.yaml \
  --freeze-dir /data/shouhanyu/Tiara2/baselines/v2.2.0 \
  --profile safe --apply --yes
```

### 6. Optional maximum-space cleanup

First print and inspect the plan:

```bash
tiara2 cleanup-baseline --config config/config.yaml \
  --freeze-dir /data/shouhanyu/Tiara2/baselines/v2.2.0 \
  --profile reproducible --release-upstream
```

Then apply the same policy only after checking `cleanup_plan.json`:

```bash
tiara2 cleanup-baseline --config config/config.yaml \
  --freeze-dir /data/shouhanyu/Tiara2/baselines/v2.2.0 \
  --profile reproducible --release-upstream \
  --apply --yes --acknowledge-upstream-loss
```

This retains the exact model-input train/validation FASTA, baseline metadata,
logs/reports, published models and declared benchmarks, while deleting derived
artifacts and configured upstream corpus copies. It deliberately refuses to
delete `base`, `fast_base`, `data_home`, or any path intersecting protected data.

## What to do after cleanup

1. Freeze the v2.3.0 label tree and data contract:
   - root: `euk_nuclear / prok / organelle / virus`
   - euk: `fungi / land_plant / algae / metazoa_vertebrate /
     metazoa_invertebrate / alveolata / stramenopiles / other_protist`
   - prok: `bacteria / archaea`
   - organelle: `mitochondria / plastid`
   - `unknown` comes from calibrated abstention, not a catch-all training class.
2. Repair split semantics before training:
   nuclear genome and its organelles must share species-level split; virus uses
   genome/vOTU-cluster split with a held-out virus benchmark.
3. Build v2.3.0-H0 first: shared encoder + hierarchical CE heads, no virus.
4. Build H1: add the explicit virus root class and giant-virus stratification.
5. Build H2: temperature scaling and branch-specific abstention thresholds.
6. Evaluate root, conditional branch and end-to-end metrics separately, plus
   lineage-level CV, per-rank F1, ECE, coverage-vs-accuracy and viral→euk FPR.
