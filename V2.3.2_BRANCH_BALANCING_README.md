# Tiara2 v2.3.2: hierarchical branch balancing

This experiment changes only the training sampler. It reuses the frozen v2.3.1
composite feature rows, labels, splits, model architecture and optimizer
contract.

The sampler first gives one third of probability mass to each root branch. It
then applies the frozen roadmap proportions inside `euk_nuclear`. Requested Euk
leaf oversampling is capped at 4x its natural share. No inverse-frequency loss
is combined with the sampler.

Within each Euk leaf, accession, species and genus probability shares are
audited and capped. The initial 5% values in the config are candidates and must
be explicitly confirmed before formal training. Taxids missing from the frozen
taxdump receive a species-specific synthetic genus key, preventing unrelated
donors from being merged while leaving accession/species caps active.

Run from the repository root:

```bash
scripts/run_v2_3_2_branch_balancing.sh index
scripts/run_v2_3_2_branch_balancing.sh dry-run
# only after confirming donor caps
scripts/run_v2_3_2_branch_balancing.sh train
```

The dry run writes `sampling_plan.json` into the configured model directory.
The formal train command uses eight GPUs through `torchrun`; rank 0 records the
same plan in every checkpoint and in the model directory.
