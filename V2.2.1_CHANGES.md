# Tiara2 v2.2.1 — k-mer search

## Design decision

v2.2.1 uses **train a model bank once, benchmark the Cartesian product later**.
For `n1` first-stage k values and `n2` second-stage values, training builds
`n1 + n2` independent models; k-search evaluates `n1 × n2` inference plans.
It does **not** retrain an entire two-stage pack for every pair.

This is preferable because each stage/k model is independent, feature and
TF-IDF caches are reusable, and only end-to-end inference reveals the interaction
between the two stages. The selected plan is the fastest plan whose benchmark
metric is within `objective.max_metric_drop` of the highest observed metric.
The JSON report also records the full accuracy/throughput Pareto frontier.

## Workflow

```bash
# 1. Configure candidate ranges and benchmark panels in config/config.yaml.
# 2. Train and publish the model bank.
tiara2 run --from train --to publish

# 3. Benchmark every first-k × second-k pair.
tiara2 run --only k_search

# 4. Use the selected frozen plan for normal inference.
tiara2 run --only infer --set infer.enabled=true
# config.yaml already points infer.manifest at k_search/best_inference_manifest.json
```

## Benchmark truth format

Each panel needs a FASTA and a tab-separated truth file:

```text
sequence_id\tlabel
contig_001\tbacteria
contig_002\teukarya
contig_003\tmitochondrion
```

Supported final labels are `archaea`, `bacteria`, `eukarya`,
`mitochondrion`, `plastid`, and `unknown`; common short aliases are normalized.

## Outputs

- `k_search_results.json`: full per-panel metrics, timings, Pareto frontier and winner.
- `k_search_results.csv`: compact comparison table.
- `best_inference_manifest.json`: exact model pair for downstream `infer`.
- `candidates/*/metrics.json`: reproducible record for every pair.
