# v2.2.0 — k-range single-factor experiment

v2.2.0 starts from the validated v2.1.3 pipeline and changes **only** the two
k-mer lists used by TF-IDF, feature caching, HP search, final training and
publishing:

```yaml
k_first:  [5, 6, 7]
k_second: [5, 6, 7, 8]
```

## Why this combination

v2.1.3 HP mean F1 ranked first-stage k5/k6 above k4, and second-stage improved
monotonically from k4 through k7. The new ranges drop the weakest k4 while
preserving the model counts (3 first-stage, 4 second-stage), so benchmark deltas
remain attributable to k range rather than ensemble/model count.

## Corpus and controls held fixed

- Reuses `/ssd/shouhanyu/Tiara2/corpus_ready_v2_1_3_bpbalanced` byte-for-byte.
- `corpus_tag` remains `v2_1_2`; no acquire/curate/chop/dedup/regroup change.
- Train/validation remain bp-balanced; test remains the untouched symlink.
- HP budgets, class weighting, collapse thresholds, network search space,
  epochs, batch sizes and final training row cap are unchanged.
- TF-IDF, seqpack, feature cache, logs, models and reports use fresh `v2_2_0`
  paths. Never symlink v2.1.3 feature/TF-IDF artifacts because their dimensions
  do not match the new k lists.

## Dynamic-k pipeline fix

v2.1.3 exposed k lists in config, but final TF-IDF and final-model validation
still hard-coded `(4,5,6)` / `(4,5,6,7)`. v2.2.0 removes that split brain:

- TF-IDF accepts `--k-first/--k-second` and stores them in its signature.
- Final trainer accepts the lists, reads matching HP JSON/cache/TF-IDF only,
  and writes a manifest for exactly those jobs.
- Publish derives model counts from list lengths.
- Config rejects empty, duplicated, unsorted or out-of-range k lists, and
  rejects stale `publish.first_count/second_count` mirrors.

## Resource warning

Feature dimensionality is `4**k`. Estimated from v2.1.3:

- first k7 cache may be about 184 GiB (train+validation),
- second k8 cache may be about 62 GiB,
- total v2.2.0 cache is expected around 310–330 GiB.

Do not add first k8 without a separate resource plan.
